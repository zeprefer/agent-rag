# 产品需求文档

## 1. 产品定位

本项目是一个面向企业内部知识的 AI Agent 系统。企业管理员可以上传制度、产品资料、技术手册、合同模板、FAQ、培训材料等专业知识文档，系统将文档解析、切片、向量化并纳入企业知识库。用户在用户端提出问题后，系统通过 RAG 技术从知识库中检索相关内容，并调用阿里云百炼平台模型生成有依据、可追溯的回答。

## 2. 用户角色

### 2.1 管理员

- 管理企业空间、用户、角色和权限。
- 创建和维护知识库。
- 上传 docx、doc、pdf、md 等文档。
- 查看文档解析、切片、向量化、索引状态。
- 配置 Agent 行为，包括模型、提示词、召回参数、回答风格、引用策略。
- 查看问答日志、命中片段、用户反馈和质量评估结果。

### 2.2 普通用户

- 在用户端进行企业知识问答。
- 支持纯文字提问。
- 支持上传图片并围绕图片提问。
- 支持上传文件并围绕文件内容提问。
- 查看回答引用来源。
- 对回答进行有用、无用、需人工处理等反馈。

### 2.3 审计或运营人员

- 查看系统使用情况、回答质量、敏感问题、低置信度问题。
- 导出问答日志和知识库命中报告。

## 3. 产品端划分

### 3.1 管理端

核心目标是让企业能够安全、可控地建设知识库。

功能模块：

- 登录与权限管理
- 企业空间管理
- 知识库管理
- 文档上传与版本管理
- 文档解析与索引任务管理
- 三级记忆管理
- Agent 配置
- 问答日志与效果分析

### 3.2 用户端

核心目标是让企业成员以自然语言访问企业知识。

功能模块：

- 对话首页
- 多轮问答
- 图片提问
- 文件提问
- 引用来源查看
- 历史会话
- 用户反馈

## 4. 支持的输入类型

### 4.1 管理端知识库文档

MVP 支持：

- `.docx`
- `.doc`
- `.pdf`
- `.md`

后续扩展：

- `.xlsx`
- `.pptx`
- HTML 页面
- 网页 URL 抓取
- 数据库或 API 同步

### 4.2 用户端提问材料

MVP 支持：

- 纯文字问题
- 图片上传
- 单个临时文件上传

用户上传的临时文件默认不进入企业知识库，只作为当前会话上下文使用。管理员可配置是否允许用户将文件转为知识库候选文档。

## 5. 核心业务流程

### 5.1 管理端知识库建设流程

1. 管理员创建知识库。
2. 管理员上传文档。
3. 系统保存原始文件并创建文档版本。
4. 解析服务提取正文、标题、目录、页码、表格等结构化内容。
5. 切片服务按语义和结构生成知识片段。
6. 嵌入服务调用百炼 Embedding 模型生成向量。
7. 索引服务写入向量库与元数据表。
8. 系统生成三级记忆中的企业语义记忆。
9. 管理员查看索引状态并发布知识库版本。

### 5.2 用户端问答流程

1. 用户输入问题，可附带图片或文件。
2. 系统识别输入类型并抽取可检索文本。
3. 系统改写查询，生成检索向量。
4. 系统在用户有权限访问的知识库中召回相关片段。
5. 系统进行重排、去重和上下文压缩。
6. 系统构造带引用的 Prompt。
7. 系统调用百炼模型生成回答。
8. 用户看到回答、引用来源和可选追问。
9. 系统记录问答日志、检索证据和用户反馈。

## 6. 非功能需求

### 6.1 安全

- 所有知识库、文档、会话都必须归属于企业空间。
- 检索必须按用户权限过滤。
- 文件上传需做类型、大小和病毒扫描预留。
- API Key 只允许通过环境变量或密钥管理服务注入。
- 问答日志中应避免明文保存敏感附件内容。

### 6.2 可追溯

- 回答需要尽量提供引用来源。
- 引用至少包含文档名、页码或章节、片段 ID。
- 管理端能查看每次回答命中的知识片段。

### 6.3 可观测

- 记录文档处理任务状态。
- 记录模型调用耗时、Token 用量、失败原因。
- 记录检索召回分数和重排结果。

### 6.4 可扩展

- 模型供应商通过 Provider 接口抽象。
- 向量库优先使用 PostgreSQL + pgvector，后续可替换为 Milvus、Elasticsearch/OpenSearch 或专用向量数据库。
- 文档解析、向量化、索引构建通过异步任务解耦。

## 7. MVP 验收标准

- 管理端可创建知识库并上传 pdf、docx、md 文档。
- 系统能完成文档解析、切片、向量化、索引。
- 用户端可基于知识库进行文字问答。
- 回答包含引用来源。
- 后端通过环境变量接入阿里云百炼模型。
- 基础日志、任务状态、错误信息可在管理端查看。
