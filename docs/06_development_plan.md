# 分批开发计划

## 第 0 批：产品文档

目标：明确产品范围、架构、数据模型、API 和开发节奏。

交付：

- 产品需求文档
- 系统架构设计
- 三级记忆与 RAG 设计
- 数据模型草案
- API 草案
- 分批开发计划

状态：已生成。

## 第 1 批：后端基础工程

目标：搭建 Python 后端骨架。

交付：

- FastAPI 项目结构
- 配置系统
- PostgreSQL 连接
- Alembic 迁移
- Redis 连接
- JWT 登录
- 租户、用户、角色基础表
- Docker Compose 本地环境

状态：已完成基础骨架。

验收：

- 本地可启动 API 服务。
- Swagger 文档可访问。
- 能创建管理员并登录获取 Token。

## 第 2 批：知识库与文档上传

目标：完成管理端知识库和文档上传后端能力。

交付：

- 知识库 CRUD
- 文档上传接口
- 对象存储接入
- 文档版本管理
- 文件类型和大小校验
- 文档处理任务表

状态：已完成知识库、文档上传、对象存储和文档版本基础能力。文档处理任务表将在第 3 批解析/切片任务链路中补齐。

验收：

- 管理员能创建知识库。
- 管理员能上传 docx、doc、pdf、md。
- 数据库可看到文档和版本记录。
- 对象存储可看到原始文件。

## 第 3 批：文档解析、切片、向量化

目标：完成知识入库主链路。

交付：

- PDF 解析
- DOCX 解析
- DOC 转换后解析
- Markdown 解析
- 语义切片
- 百炼 Embedding 调用封装
- pgvector 索引写入
- 任务失败重试

验收：

- 上传文档后可自动生成 chunk。
- chunk 可生成 embedding。
- 文档状态可从 uploaded 变为 indexed。

## 第 4 批：RAG 问答后端

目标：完成用户文字问答。

交付：

- 会话管理
- 消息管理
- 查询向量化
- 权限过滤检索
- Top K 召回
- Prompt 构造
- 百炼 Chat 调用
- 引用来源返回
- 非流式和流式接口

验收：

- 用户可基于知识库提问。
- 回答包含引用来源。
- 无相关内容时能明确说明资料不足。

## 第 5 批：管理端前端

目标：提供可用的企业知识库管理界面。

交付：

- 登录页
- 知识库列表
- 文档上传
- 文档状态查看
- 文档详情
- Agent 配置
- 问答日志

验收：

- 管理员可在浏览器完成知识库创建和文档上传。
- 可查看解析和索引状态。

## 第 6 批：用户端前端

目标：提供用户问答界面。

交付：

- 对话界面
- 历史会话
- 流式回答
- 引用来源展示
- 图片上传提问
- 文件上传提问
- 反馈按钮

验收：

- 用户可完成多轮问答。
- 能查看引用来源。
- 能上传图片或文件作为问题上下文。

## 第 7 批：质量、安全与部署

目标：让系统具备企业试用条件。

交付：

- 问答质量评估
- 检索日志分析
- 敏感信息处理
- API 限流
- 文件安全扫描预留
- Docker Compose 完整部署
- 基础监控日志

验收：

- 系统可在测试环境稳定运行。
- 管理员可排查模型调用、检索和解析问题。

## 开发顺序建议

建议下一步进入第 1 批：后端基础工程。原因是后端数据模型、权限、任务队列和模型配置会决定后续管理端、用户端、RAG 链路的接口形态。
