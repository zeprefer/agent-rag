# User Attachment RAG Notes

## Purpose

User attachments are temporary context for a chat session. They let users ask questions about an image or file while still using enterprise knowledge-base retrieval for answer grounding.

Attachments are not added to the enterprise knowledge base and are not indexed as reusable organizational memory.

## Backend Flow

1. User uploads an attachment to `POST /api/v1/chat/sessions/{session_id}/attachments`.
2. The backend stores the raw attachment in object storage.
3. For files, the backend extracts text using the existing document parser.
4. For images, the backend calls the Bailian/DashScope vision model and stores a textual description/OCR-style context.
5. User sends a question with `attachment_ids`.
6. The backend combines the user question and attachment text for retrieval.
7. The backend adds attachment context to the final RAG prompt.
8. The answer is generated by Bailian/DashScope Chat and returned with enterprise knowledge citations.

## New Environment Variables

```env
BAILIAN_VISION_MODEL=qwen-vl-plus
MAX_CHAT_ATTACHMENT_SIZE_MB=20
SUPPORTED_CHAT_FILE_EXTENSIONS=docx,doc,pdf,md,txt
SUPPORTED_CHAT_IMAGE_EXTENSIONS=png,jpg,jpeg,webp
```

## New API

- `POST /api/v1/chat/sessions/{session_id}/attachments`
- `GET /api/v1/chat/sessions/{session_id}/attachments`

`POST /api/v1/chat/sessions/{session_id}/messages` now accepts:

```json
{
  "content": "请结合附件和公司知识库回答",
  "attachment_ids": ["uuid"]
}
```

## Frontend Flow

The user console at `frontend/user` now supports selecting multiple files/images in the message composer. On send, the frontend uploads each attachment first, then submits the question with returned attachment IDs.
